# Лабораторная работа №1: статистика компании лифтов

## Предметная область

Компания обслуживает лифты в нескольких зданиях и непрерывно получает от них телеметрию. Один объект `ElevatorTelemetry` — состояние конкретного лифта в определённый момент времени. При реальной частоте отправки данных несколько раз в секунду коллекция из 250 000 событий является обычным объёмом данных.

В проекте реализованы три базовых класса и отдельный генератор для каждого:

1. `Building` — характеристики здания.
2. `Elevator` — характеристики лифта.
3. `ElevatorTelemetry` — массовый объект телеметрии.

Массовый класс содержит все требуемые типы:

| Требуемый тип | Поле |
| --- | --- |
| `long`, `int`, `double` | `eventId`, `passengerCount`, `loadKg`, `speedMetersPerSecond` |
| `String` | `sensorId` |
| дата/время | `LocalDateTime capturedAt` |
| `enum` | `ElevatorState state` |
| `record` | `FloorPosition position` |
| коллекция | `Set<AlarmCode> activeAlarms` |

Генераторы создают уникальные объекты со случайными, но согласованными значениями. Например, неподвижный лифт имеет нулевую скорость, этаж входит в диапазон здания, а превышение грузоподъёмности обязательно сопровождается сигналом `OVERLOAD`.

## Рассчитываемая статистика

Все три алгоритма возвращают одинаковый `FleetStatistics`:

- общее число событий телеметрии;
- количество срабатываний аварий каждого типа;
- для каждого состояния лифта — число событий, минимальная, средняя, максимальная и суммарная наблюдаемая нагрузка.

Способы расчёта:

1. Императивный цикл по коллекции.
2. Последовательный Stream API со стандартными `groupingBy`, `summarizingDouble`, `flatMapping`, `counting` и `teeing`.
3. Stream API с собственным `ElevatorStatisticsCollector`.

Собственный коллектор имеет `supplier`, `accumulator`, `combiner`, `finisher` и характеристику `UNORDERED`.

## Запуск на Windows

Установить JDK 17 или более новую версию и выполнить в папке проекта:

```powershell
.\run.bat
```

Скрипт сам компилирует исходники и запускает программу. Maven и сторонние библиотеки не требуются. Размеры коллекций заданы прямо в `App.java`.

## Запуск на Linux или macOS

```bash
chmod +x run.sh
./run.sh
```

## Запуск через IntelliJ IDEA

1. Открыть папку `elevator-statistics-lab` как проект.
2. Выбрать установленный JDK 17 или JDK 21.
3. Дождаться импорта `pom.xml`.
4. Запустить метод `main` класса `ru.itmo.reactivejava.elevator.App`.

## Запуск через Maven

```bash
mvn clean package
java -jar target/elevator-statistics-lab-1.0.0.jar
```

## Как устроен эксперимент

Для размеров 5 000, 50 000 и 250 000 программа:

1. Генерирует одну коллекцию вне измеряемого участка.
2. Фиксирует начало и окончание каждого расчёта через `System.nanoTime()`.
3. Проверяет совпадение результатов трёх алгоритмов.
4. Выводит время выполнения и итоговую статистику.

Результаты времени нельзя переносить в отчёт с другого компьютера: их следует получить на том устройстве, на котором выполняется финальный эксперимент.

## Перенос между компьютерами

Проект не содержит абсолютных путей и привязки к IntelliJ IDEA. Достаточно перенести всю папку или архив проекта. Папку `target` переносить необязательно — она создаётся заново. На втором компьютере требуется только JDK 17+.

## Развитие темы в следующих лабораторных

Каждый лифт можно сделать независимым производителем событий. События разных лифтов обрабатываются параллельно, но порядок событий одного лифта сохраняется. Предметная область естественно поддерживает:

- `ExecutorService` и отдельные задачи генерации для лифтов;
- ограниченную `BlockingQueue` между производителями и обработчиками;
- параллельные потоки и собственный коллектор;
- Java Flow API, RxJava или Project Reactor;
- объединение потоков, группировку по лифтам и backpressure.
